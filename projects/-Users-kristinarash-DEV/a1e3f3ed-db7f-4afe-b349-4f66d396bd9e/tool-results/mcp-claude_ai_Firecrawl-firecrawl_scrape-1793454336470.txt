To use them, send the `TypeSafe-Danger-Zone-Images: true` header with each request that contains an image or a Box question. The examples under [Uploading images](https://docs.typesafe.ai/images#uploading-images) show how. The other examples on this page show only the request body.\n\n## [​](https://docs.typesafe.ai/images\\#sending-images-in-a-request)  Sending images in a request\n\nEach image is listed once, in the request’s top-level `assets` map. Its key in that map is a reference string. Write the reference wherever the image belongs, as a whole string value or inside a longer string, and the model receives the image in its place.This request sends a photo of a found dog as the state, and puts the photo from a lost-dog poster directly into one question:\n\n```\n{\n  \"model\": \"jev-latest\",\n  \"state\": {\n    \"photo\": \"a3f1c2e8-found\"\n  },\n  \"assets\": {\n    \"a3f1c2e8-found\": {\"type\": \"image\", \"format\": \"jpg\", \"data_base64\": \"/9j/4AAQSkZJRg...\"},\n    \"77b0d4a1-poster\": {\"type\": \"image\", \"format\": \"jpg\", \"data_base64\": \"/9j/4AAQSkZJRg...\"}\n  },\n  \"questions\": {\n    \"same_dog\": {\n      \"type\": \"noul\",\n      \"instructions\": \"Is the dog in `photo` the same dog as in this picture: 77b0d4a1-poster?\"\n    },\n    \"has_collar\": {\n      \"type\": \"noul\",\n      \"instructions\": \"Is the dog in `photo` wearing a collar?\"\n    },\n    \"coat\": {\n      \"type\": \"choice\",\n      \"instructions\": \"What is the coat of the dog in `photo` like?\",\n      \"criteria\": {\n        \"short\": \"Short and smooth.\",\n        \"long\": \"Long or feathered.\",\n        \"curly\": \"Curly or wiry.\"\n      }\n    }\n  }\n}\n```\n\nQuestions can refer to an image in the state by name or path in backticks, the same way they refer to any other field (see [Reference specific fields](https://docs.typesafe.ai/primitives#reference-specific-fields)). An image that only one question uses goes directly in that question’s `instructions` or `criteria`, as the poster photo does above.Jev 1.13 and Jev 1.14 both accept images. [Box](https://docs.typesafe.ai/primitives/box) questions need Jev 1.14.\n\n### [​](https://docs.typesafe.ai/images\\#asset-fields)  Asset fields\n\n[​](https://docs.typesafe.ai/images#param-assets)\n\nassets\n\nmap<string, Asset>\n\nThe images in the request, keyed by reference string. Every reference must appear somewhere in the `state`, `instructions`, or `criteria`.\n\nShowAsset properties\n\n[​](https://docs.typesafe.ai/images#param-type)\n\ntype\n\n\"image\"\n\nThe kind of asset. Optional. If you send it, it must be `\"image\"`.\n\n[​](https://docs.typesafe.ai/images#param-part)\n\npart\n\nstring\n\nIn a multipart request, the name of the file part that holds the image. See [Uploading images](https://docs.typesafe.ai/images#uploading-images).\n\n[​](https://docs.typesafe.ai/images#param-data-base64)\n\ndata\\_base64\n\nstring\n\nThe image file, base64-encoded. Required unless `part` is set. Use the standard base64 alphabet with `=` padding, no line breaks or other whitespace, and no `data:` prefix.\n\n[​](https://docs.typesafe.ai/images#param-format)\n\nformat\n\n\"png\" \\| \"jpg\" \\| \"jpeg\"\n\nThe image’s format, in lowercase. Required with `data_base64`. Optional with `part`. `\"jpeg\"` is another name for `\"jpg\"`.\n\nSend each image one way, with `part` or `data_base64`. If an asset has both, the API uses `part`.\n\n### [​](https://docs.typesafe.ai/images\\#references)  References\n\nReferences are matched as plain text anywhere in the request’s strings, so a reference works mid-sentence as well as as a whole value. A short reference such as `cat` could also match inside `category`. Use references that can’t occur in your text by accident. A new UUID for each image in each request is the safest choice.\n\n- **Every asset must be referenced.** A request with an asset that is not referenced anywhere returns `400`.\n- **Whole values match first.** A string that is exactly a reference becomes that image. In longer strings, references are replaced from left to right, and matches never overlap.\n- **Each use adds the image again.** The file is uploaded once, but every place its reference appears adds another copy of the image to what the model reads, and every copy counts toward the [expanded request limit](https://docs.typesafe.ai/images#limits).\n- **Object keys are not replaced.** A Choice option name, a question ID, or any other object key stays text. To define a Choice option with a picture, put the reference in the option’s description, as in [Criteria](https://docs.typesafe.ai/images#criteria).\n- **Answers contain the reference, not the image,** wherever they repeat your criteria, such as a Score’s `legend`.\n- **Keep keys short.** Each reference can be at most 1,024 bytes of UTF-8, and all references in a request together at most 65,536 bytes. These limits count bytes, not characters. A reference can’t be empty or only whitespace.\n\nThe Python and JavaScript SDKs create references for you. See [Uploading images](https://docs.typesafe.ai/images#uploading-images).\n\n## [​](https://docs.typesafe.ai/images\\#uploading-images)  Uploading images\n\nWith the latest Python or JavaScript SDK, put an image object anywhere text can go. The SDK creates a reference for it and uploads the file. This example sends one doorbell photo as the state and asks two questions about it:\n\nPython\n\nJavaScript\n\n```\nfrom pathlib import Path\n\nfrom typesafe_sdk import Choice, Image, Noul, TypeSafeClient\n\nwith TypeSafeClient() as client:\n    result = client.system_one(\n        state={\"door\": Image(Path(\"door-camera.jpg\"))},\n        questions={\n            \"person_present\": Noul(instructions=\"Is there a person in `door`?\"),\n            \"carrying\": Choice(\n                instructions=\"What is the person in `door` carrying?\",\n                criteria={\n                    \"package\": \"A box or parcel.\",\n                    \"bag\": \"A bag of groceries or shopping.\",\n                    \"nothing\": \"Empty hands.\",\n                },\n            ),\n        },\n        extra_headers={\"TypeSafe-Danger-Zone-Images\": \"true\"},\n    )\n    print(result.answers)\n```\n\n```\nimport { openAsBlob } from \"node:fs\";\nimport { choice, image, noul, TypeSafeClient } from \"@typesafe-ai/sdk\";\n\nconst client = new TypeSafeClient();\nconst door = image(await openAsBlob(\"door-camera.jpg\"));\n\nconst { answers } = await client.systemOne(\n  {\n    state: { door },\n    questions: {\n      person_present: noul(\"Is there a person in `door`?\"),\n      carrying: choice(\"What is the person in `door` carrying?\", {\n        package: \"A box or parcel.\",\n        bag: \"A bag of groceries or shopping.\",\n        nothing: \"Empty hands.\",\n      }),\n    },\n  },\n  { headers: { \"TypeSafe-Danger-Zone-Images\": \"true\" } },\n);\nconsole.log(answers);\n```\n\nTo put an image inside a sentence, or to choose your own references, see the [SDK guides](https://docs.typesafe.ai/sdk).\n\n### [​](https://docs.typesafe.ai/images\\#over-http)  Over HTTP\n\nWithout an SDK, send each image as a file part in a `multipart/form-data` request. Multipart is the better choice: it sends the file as it is, while base64 makes each image about a third larger, and that extra size counts toward the 32 MiB [request body limit](https://docs.typesafe.ai/images#limits). Base64-encode images into the JSON only when you can’t send multipart.\n\n- Multipart (recommended)\n\n- Base64 in JSON\n\n\nSend the JSON body as the first part, named `request`, with content type `application/json`. Send each image as its own file part, and set that image’s `part` in `assets` to the file part’s name:\n\n```\ncurl https://api.typesafe.ai/v1/systemone \\\n  -H \"Authorization: Bearer $TYPESAFE_API_KEY\" \\\n  -H \"TypeSafe-Danger-Zone-Images: true\" \\\n  -F 'request={\n    \"model\": \"jev-latest\",\n    \"state\": {\"door\": \"a3f1c2e8-door\"},\n    \"assets\": {\"a3f1c2e8-door\": {\"type\": \"image\", \"part\": \"door-photo\"}},\n    \"questions\": {\n      \"person_present\": {\"type\": \"noul\", \"instructions\": \"Is there a person in `door`?\"}\n    }\n  };type=application/json' \\\n  -F 'door-photo=@door-camera.jpg;type=image/jpeg'\n```\n\nThe rules for multipart requests:\n\n- The first part is named `request` and holds the JSON body.\n- Part names are unique and not empty. `request` is reserved for the JSON body.\n- Each image part has content type `image/png`, `image/jpeg`, `image/jpg`, or `application/octet-stream`, or no content type. Any other content type returns `400`.\n- Each file part belongs to exactly one asset. A part that no asset names, two assets that name the same part, and an asset whose part is missing all return `400`.\n\nTo use the same image in several places, write its reference in each of them.\n\nBase64-encode the file into `data_base64` and set `format`, following the rules in [Asset fields](https://docs.typesafe.ai/images#asset-fields). Python’s `base64.b64encode` produces the right encoding. This Python example sends one photo and asks two questions about it:\n\n```\nimport base64\nimport os\nimport uuid\n\nimport requests\n\ndef image_asset(path: str) -> tuple[str, dict]:\n    \"\"\"Return a new reference and the asset entry for one image file.\"\"\"\n    fmt = \"png\" if path.lower().endswith(\".png\") else \"jpg\"\n    with open(path, \"rb\") as f:\n        data = base64.b64encode(f.read()).decode(\"ascii\")\n    return str(uuid.uuid4()), {\"type\": \"image\", \"format\": fmt, \"data_base64\": data}\n\nphoto_key, photo = image_asset(\"door-camera.jpg\")\n\nresponse = requests.post(\n    \"https://api.typesafe.ai/v1/systemone\",\n    headers={\n        \"Authorization\": f\"Bearer {os.environ['TYPESAFE_API_KEY']}\",\n        \"TypeSafe-Danger-Zone-Images\": \"true\",\n    },\n    json={\n        \"model\": \"jev-latest\",\n        \"state\": {\"door\": photo_key},\n        \"assets\": {photo_key: photo},\n        \"questions\": {\n            \"person_present\": {\n                \"type\": \"noul\",\n                \"instructions\": \"Is there a person in `door`?\",\n            },\n            \"carrying\": {\n                \"type\": \"choice\",\n                \"instructions\": \"What is the person in `door` carrying?\",\n                \"criteria\": {\n                    \"package\": \"A box or parcel.\",\n                    \"bag\": \"A bag of groceries or shopping.\",\n                    \"nothing\": \"Empty hands.\",\n                },\n            },\n        },\n    },\n)\nprint(response.json()[\"answers\"])\n```\n\n## [​](https://docs.typesafe.ai/images\\#image-placement)  Image placement\n\n### [​](https://docs.typesafe.ai/images\\#state)  State\n\nImages in the `state` are part of the state, the same as any text or JSON there. The model evaluates them together with the rest of the state, and every question in the request is evaluated against them. A state can mix images with text, and can hold several images, labeled or nested like any other state data. This state holds a short history of camera frames, oldest first:\n\n```\n{\n  \"state\": {\n    \"frames\": [\\\n      {\"seconds_ago\": 2, \"frame\": \"5c0e9a12-f1\"},\\\n      {\"seconds_ago\": 1, \"frame\": \"1d7be0c4-f2\"},\\\n      {\"seconds_ago\": 0, \"frame\": \"e48a6f30-f3\"}\\\n    ]\n  }\n}\n```\n\nA question can ask “Did the door in `frames` open during these frames?” or refer to one frame by path, such as ```frames[2].frame```.\n\n### [​](https://docs.typesafe.ai/images\\#instructions)  Instructions\n\nAn image in a question’s `instructions` is part of that question and is sent only with that question. Put the reference in the sentence where the question needs the image:\n\n```\n{\n  \"state\": {\"door\": \"e48a6f30-door\"},\n  \"questions\": {\n    \"is_badge_holder\": {\n      \"type\": \"noul\",\n      \"instructions\": \"Is the person in `door` the same person as in this badge photo: 9a21c7d3-badge?\"\n    }\n  }\n}\n```\n\nAn image in `instructions` is sent to the model once for every question that includes it. When several questions use the same image, put it in the `state` once and refer to it by path from each question. That uses fewer tokens and less of the [size limits](https://docs.typesafe.ai/images#limits).\n\n### [​](https://docs.typesafe.ai/images\\#criteria)  Criteria\n\nChoice options, Score levels, and Noul `true` and `false` definitions can each include images. This Choice classifies a hand gesture, with each option defined by example pictures. The option names are the values your code receives in `choice`, and the pictures are what the model compares the hand against:\n\n```\n{\n  \"state\": {\"camera\": \"e48a6f30-cam\"},\n  \"questions\": {\n    \"gesture\": {\n      \"type\": \"choice\",\n      \"instructions\": \"Which gesture is the hand in `camera` making?\",\n      \"criteria\": {\n        \"thumbs_up\": \"0b6c51aa-thumb\",\n        \"open_palm\": {\n          \"description\": \"A hand held up with the palm facing the camera.\",\n          \"examples\": [\"4fd2e7b9-palm1\", \"c83a0e15-palm2\"]\n        },\n        \"fist\": \"a7e94d02-fist\",\n        \"none\": \"No hand, or a hand that matches none of the examples.\"\n      }\n    }\n  }\n}\n```\n\nAn option can be an image on its own (`thumbs_up`), a description with one or more examples (`open_palm`), or text only (`none`). The `description` and `examples` keys are names chosen for this example, not required fields: criteria accept any [structure](https://docs.typesafe.ai/images#structured-data).Score and Noul criteria take images the same way:\n\n- **Score levels** can each include an example picture. A Score for how open a hand is could use a closed fist, a half-open hand, and an open hand as its three levels.\n- **Noul criteria** can define `true` and `false` with pictures: `{\"true\": {\"description\": \"Correctly assembled\", \"examples\": [\"<reference>\"]}, \"false\": \"Parts missing or in the wrong place.\"}`.\n\n### [​](https://docs.typesafe.ai/images\\#structured-data)  Structured data\n\nState, instructions, and criteria accept nested JSON [structure](https://docs.typesafe.ai/primitives/advanced), and a reference works at any level of it. A question can refer to one picture in an array as ```lineup[2]```, or to one in a labeled object as ```faces.happy```. A criterion can hold several example pictures as an array.\n\n## [​](https://docs.typesafe.ai/images\\#patterns)  Patterns\n\n| Pattern | How it works | Where the image goes |\n| --- | --- | --- |\n| Compare against a known picture | Ask whether the state shows the same person, product, or place as a known picture. | Known picture in `instructions`, photo in `state` |\n| Define options by example | Define each Choice option with one or a few example pictures. | `criteria` |\n| What changed | Send the previous frame or a short frame history, and ask about motion, arrivals, or differences. | `state` |\n| Look closer when needed | Ask about a small copy of the image first. Send a larger copy (up to the size limit), or a full-resolution crop, only when the answer needs more detail. | `state` |\n| Search a large image | Cut the image into tiles and ask a Choice with the tiles as its options. Repeat on the chosen tile until the target takes up most of the tile. | `criteria` |\n| Find where it is | Ask a [Box](https://docs.typesafe.ai/primitives/box) question for the edges of the target. | `state`, optionally a picture of the target in `instructions` |\n\n## [​](https://docs.typesafe.ai/images\\#limits)  Limits\n\n| Limit | Value |\n| --- | --- |\n| Format | PNG or JPEG, still images only. Animated PNGs are rejected. |\n| File size | 16 MiB per image file. For base64, this is the size after decoding. |\n| Width and height | 280 to 1568 pixels each. An image with either side under 280 pixels is rejected. |\n| Total pixels (width × height) | 78,400 to 2,458,624, the area of a 280 × 280 to a 1568 × 1568 square. |\n| Request body | 32 MiB, including the JSON, base64 text, and multipart framing. HTTP headers don’t count. [Compression](https://docs.typesafe.ai/api/errors#compression) doesn’t raise the limit. |\n| All images in the request | 32 MiB, shared by every distinct image after the API processes it. Processing re-encodes each image and can make it larger than the file you sent, so a request of small uploads can still go over. |\n| Expanded request | 32 MiB for the text, questions, structure, and images after every reference is replaced by its image. Each use of a reference adds the image again: an image that is 10 MiB after processing, referenced four times, is over the limit. |\n\nAll limits include both ends of the range. An image outside them is rejected, never resized to fit. If any image in a request is rejected, the whole request fails: there are no partial answers. See [Errors](https://docs.typesafe.ai/images#errors) for the status codes.How many images fit in one request depends on these limits and on the [context length](https://docs.typesafe.ai/models). Images have no separate [rate limits](https://docs.typesafe.ai/api/errors#handling-rate-limits): a request with images counts against the same limits as any other request.To stay under the request limits, send fewer images, send smaller images, put an image that several questions use in the `state` once instead of in each question’s `instructions`, or split the work across requests.\n\n## [​](https://docs.typesafe.ai/images\\#preparing-images)  Preparing images\n\nSend each image as a PNG or JPEG, rotated upright and sized within the [limits](https://docs.typesafe.ai/images#limits). Prepare each one before you send it:\n\n- **Resize before sending.** Scale the image so its longest side is at most 1568 pixels. A typical 12-megapixel phone photo becomes 1568 × 1176. Scale up, or pad, an image smaller than the minimum.\n- **Rotate the pixels upright.** The API removes all metadata (EXIF, color profiles, comments) and does not apply the EXIF orientation. A photo that looks upright in your photo viewer can reach the model sideways, so rotate the pixels themselves first.\n- **Send a still image.** For an animation or a video, export the frame you want as a PNG or JPEG. Convert other formats, such as GIF, WebP, or HEIC, to PNG or JPEG.\n- **Prefer standard JPEG.** A standard 8-bit baseline JPEG is the safest JPEG to send. Re-save progressive JPEGs as baseline.\n- **Re-export a rejected file.** If the API rejects a file that opens fine on your computer, open it in a standard image editor or library and export it again as PNG or JPEG.\n\nThis Python example uses the Pillow library to prepare one photo:\n\n```\nfrom PIL import Image, ImageOps\n\nwith Image.open(\"photo.jpg\") as original:\n    img = ImageOps.exif_transpose(original)  # rotate the pixels upright\n    img.thumbnail((1568, 1568))  # longest side at most 1568, same aspect ratio\n    # thumbnail only shrinks: upscale or pad an image under the minimum separately\n    img.convert(\"RGB\").save(\"photo-ready.jpg\", \"JPEG\", quality=90)  # baseline JPEG\n```\n\n## [​](https://docs.typesafe.ai/images\\#image-tokens)  Image tokens\n\nEach image counts as input tokens, billed at the same per-token [input price](https://docs.typesafe.ai/models) as text. There is no separate charge for images. The `usage.input_tokens` field in the response includes the tokens for every image in the request. Image tokens also count toward the request’s [context length](https://docs.typesafe.ai/models).We’ll be providing guidance on estimating image token usage soon.\n\n## [​](https://docs.typesafe.ai/images\\#errors)  Errors\n\n| Status | Cause |\n| --- | --- |\n| `400` | Images are not turned on: the request has an image or a Box question but no `TypeSafe-Danger-Zone-Images: true` header. See [Turning on images](https://docs.typesafe.ai/images#turning-on-images). |\n| `400` | An image or asset was rejected. The file isn’t PNG or JPEG, is damaged or incomplete, or is animated; the image is below the minimum width, height, or total pixels; an asset isn’t referenced anywhere; the base64 or `format` is invalid; a reference is empty; or the multipart request breaks a [multipart rule](https://docs.typesafe.ai/images#over-http). |\n| `400` | `max_tokens_exceeded`: the images and text together exceed the request’s [context length](https://docs.typesafe.ai/models). Send fewer or smaller images, or move images out of `instructions` into the `state`. |\n| `413` | The request is over a size limit: an image file, an image’s width, height, or total pixels, the request body, all images together, the expanded request, or the reference lengths. See [Limits](https://docs.typesafe.ai/images#limits). |\n\nIf a request has several problems, the error reports one of them. Check the request against [Limits](https://docs.typesafe.ai/images#limits) and [Preparing images](https://docs.typesafe.ai/images#preparing-images).\n\nWas this page helpful?\n\nYesNo\n\n
