## The measurement

| Metric | Count |

| Plugin skills exposed per session | ~37 (6 enabled, 18 disabled) |

Everything is global. That is the anti-pattern, not the achievement.

## The rule that fixes it — promotion

**Everything stays project-level until it earns global.** A skill lives in
`<project>/.claude/skills/` until it proves itself across 2+ projects, then it
gets promoted to `~/.claude/skills/`. Keeps the global load small and the blast
radius tight — so when something underperforms you can tell a *model* problem
from a *harness* problem from an *organisation* problem.

## The audit question

Not "how often did I run this skill?" but **"would the model do this fine without
the skill now?"** A skill is a crutch; as the brain gets smarter the crutch starts
to *limit* it. Seasonal skills (`forecast-capture`) and occasional ones
(`ingest-book`) are low-count by design — low usage alone is not a delete signal.

## Re-measure (BUILTIN filter is the whole trick)

Without the `BUILTIN` set you also count `/exit`, `/clear`, `/compact` and friends,
which inflates the total to 74 and buries the real skills.

```bash
python3 - <<'EOF'
import glob,re,collections
BUILTIN={'exit','clear','compact','rename','color','login','logout','plugin','doctor',
'help','model','config','resume','cost','status','init','agents','mcp','hooks','memory',
'review','vim','terminal-setup','install-github-app','add-dir','bug','release-notes',
'pr-comments','ide','permissions','statusline','output-style','todos','export',
'privacy-settings','upgrade','fast','artifacts','tasks','loop','context','usage','rewind',
'sandbox','feedback','worktrees','skills','reload-skills','reload-plugins','bashes',
'keybindings','theme'}
c=collections.Counter()
for f in glob.glob('/Users/kristinarash/.claude/projects/**/*.jsonl',recursive=True):
    try:
        for line in open(f,encoding='utf-8',errors='ignore'):
            if 'Skill' not in line and 'command-name' not in line: continue
            for m in re.finditer(r'"name"\s*:\s*"Skill"\s*,\s*"input"\s*:\s*\{[^}]*?"skill"\s*:\s*"([^"]+)"', line):
                c[m.group(1)]+=1
            for m in re.finditer(r'<command-name>/([a-zA-Z0-9:_-]+)</command-name>', line):
                c[m.group(1)]+=1
    except Exception: pass
real={k:v for k,v in c.items() if k.split(':')[-1] not in BUILTIN and k not in BUILTIN}
print("distinct real skills ever invoked:",len(real))
print("used >=3 times:",len([k for k,v in real.items() if v>=3]))
print("used exactly once:",len([k for k,v in real.items() if v==1]))
for k,v in sorted(real.items(),key=lambda x:-x[1]): print(f"{v:5d}  {k}")
EOF
```

=== project_cloud-push-launchd-blocked
---
name: cloud-push-launchd-blocked
description: "cloud-push under launchd: macOS per-file com.apple.macl blocks it; fixed 2026-10-23 by running it inside Terminal via cloud-push-launch.sh"
metadata:
  node_type: memory
  type: project
  originSessionId: 802ea68a-c53e-4d3a-a897-1d311560fdd1
  modified: 2026-10-23T12:24:59.589Z
---

`com.keystone.clouddrivepush` (07:00 and 17:30) failed under launchd from 2026-10-12 to 10-23 with rsync `open: Operation not permitted` on `Drive/.../_MACHINE/Cloud_Copy/DEV/`. By hand from Terminal it always worked.

**Cause (tested 2026-10-23).** A process started straight by launchd (python3 or bash) can stat, mkdir and create new files in the Drive mount, and rewrite files it made itself. It cannot list Drive folders, or open, rename over, or delete files that Terminal made. Each such file carries `com.apple.macl` naming Terminal; `xattr -d` does not remove it. Full Disk Access on `Python.app`/rsync does not help (tried 10-14). rsync lists the destination, so it failed on the first step.

**Fix (live 2026-10-23).** The plist runs `/bin/bash ~/.claude/scripts/cloud-push-launch.sh`. That runs `open -g -a Terminal ~/.claude/scripts/cloud-push.command`, which runs `cloud-push.py` (rsync, unchanged) with Terminal's access. The launcher waits 90 s for a new `START` line in `cloud-push.log`; if none, it writes an ERROR to the log and to `.errors.log`. Tracked plist copy: `~/.claude/scripts/com.keystone.clouddrivepush.plist`. Proven: kickstarted runs OK 07:15 and 07:21 with the screen locked.

**Known costs.** Each run opens a Terminal window. Eric set profile "Clear Dark" to "Close if the shell exited cleanly" (10-23, in Terminal Settings; a `defaults import` did not reach the running Terminal), so the window closes when the copy ends (tested). Under memory pressure Terminal ran queued opens ~5 min late; the 90 s check would log that as an ERROR even if the copy runs later.

**How to apply:** Do not swap rsync for a launchd-run copier: Terminal-made files can never be updated that way, and a by-hand run re-taints files. By hand is still `python3 ~/.claude/scripts/cloud-push.py`, or `launchctl kickstart gui/501/com.keystone.clouddrivepush`. Off switch: `launchctl bootout gui/501/com.keystone.clouddrivepush`. Any other launchd job that must read or change Terminal-made Drive files hits the same wall; route it through Terminal the same way or use the `gws` API. See [[automation-cadence]] and [[cloud-copy-approval]].
