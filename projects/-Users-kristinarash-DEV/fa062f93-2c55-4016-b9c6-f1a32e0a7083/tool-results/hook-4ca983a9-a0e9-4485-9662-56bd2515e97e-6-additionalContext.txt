    1. GATHER: mcp__plugin_context-mode_context-mode__ctx_batch_execute(commands, queries)

    3. PROCESSING: mcp__plugin_context-mode_context-mode__ctx_execute(language, code) | mcp__plugin_context-mode_context-mode__ctx_execute_file(path, language, code)

  </tool_selection_hierarchy>

The CFB weekly forecast freeze had no Mac-side guard. It is the only ritual
protecting a non-backfillable artifact: a pre-game forecast is capturable only
before kickoff, so a missed Wednesday is a permanently absent week in the
series rather than a chore that rolls forward. Season opens 2026-08-26.

The alarm is deliberately silent in two cases that look like bugs:
  - outside the season window (Aug 26 - Jan 20), and
  - Sun/Mon/Tue after a missed week, when the window has already closed and
    no action remains.
Nagging about an unfixable thing is how an alarm teaches you to ignore it, and
this one has to still be believed on the Wednesday that matters. Live window is
Wed (DUE) -> Thu/Fri/Sat (OVERDUE), which the existing launchd schedule already
covers at Wed/Thu/Fri 17:00 plus Fri 15:30.

Also fixes -Notify, which has been mute since the Windows migration: it shelled
out to msg.exe, absent on macOS, so every scheduled run landed in the catch and
wrote 'desktop prompt unavailable' to a log nobody reads. That is precisely the
invisible-absence failure this script exists to prevent, reproduced inside its
own alarm. Now uses osascript, falling back from dialog to notification banner.

Adds -Today and -CfbSnapshotDir seams so the date- and season-dependent logic is
testable; tests/keystone-ritual-forecast-capture.ps1 pins both silent cases,
which a days-since-last-capture implementation would fail.
