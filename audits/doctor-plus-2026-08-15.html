Correction — this section was wrong

Kept visible rather than quietly rewritten, because the mistake is the useful part.

What this report originally said: that AGENTS.md and CLAUDE.md were two byte-identical hand-maintained copies (5,869 chars each) at risk of drifting apart, and that symlinking them was an optional tidy-up.

What was actually true: AGENTS.md was already a symlink to CLAUDE.md, created 2026-08-14. Identical sizes were the symptom of one file, not two.

$ ls -li ~/.claude/CLAUDE.md ~/.claude/AGENTS.md 13925526 lrwxr-xr-x AGENTS.md -> CLAUDE.md 14466983 -rw-r--r-- CLAUDE.md

The recommendation was not just redundant, it pointed the wrong way. The two files now need to diverge: CLAUDE.md routes through the Skill tool, and the harnesses that read AGENTS.md have no Skill tool, so they need the memory rules written out in prose. The symlink was actively preventing that.

How it surfaced: the first activation run copied the AGENTS content through the link and overwrote CLAUDE.md. A size check caught it within seconds — CLAUDE.md came out at 4,995 bytes when it should have been 3,130, and matching AGENTS.md exactly. Both files were rebuilt correctly, and activate.sh now removes the link first and aborts if the two ever end up identical.

Skill authoring now has one home. Three files described how to write a skill. CreateSkill is the authority; write-a-skill is a pointer to it (4,110 → 2,342 bytes); superpowers:writing-skills is a third-party plugin and cannot be edited here. CreateSkill's own description dropped 1,006 → 785 characters by moving enforcement prose into the body — all 20 trigger phrases kept verbatim, since descriptions are what make a skill fire. Done through Skill("CreateSkill") as skills/CLAUDE.md requires, not by hand.

The catch that made the whole refactor safe: NO hook injects USER.md or MEMORY.md at session start. The prose in CLAUDE.md IS the loading mechanism. Deleting that section as "redundant procedure" would have silently stopped memory from loading at all. It stayed.

Codex verified it. Rather than "review this", Codex was asked a checkable question: of the 13 behaviors the original file enforced, which are still reachable by an agent reading only the new files? Result: 11 REACHABLE, 2 DEGRADED, 0 LOST. It caught a defect that would otherwise have shipped — the memory-write skill advertised only writing, so a recall question would not reliably reach the retrieval ladder that had just been moved into it. Its four required changes were all applied, including installing the skill before the router so the corrected slug rule lands first.

Also fixed: a live bug where memory-write named a retired Windows slug as the example write target, and the twelve frontend-slides presets, which are now a rendered gallery instead of prose. Both committed to branch worktree-doctor-plus-fixes.
