# STORAGE — where every file lives

Read this before you save, move, back up, or copy any file. One rule set for every agent
(Claude Code, Codex, Gemini) on every machine. Decided by Eric 2026-10-16.

## The model

Every file has one **true copy**. Edit the true copy, or a working copy that syncs back to it
the same day. Everything else is a **backup** (machine-written, never edited) or **scratch**
(thrown away).

Drive is the one place Eric looks. Documents live there directly. Code lives in GitHub and is
mirrored into Drive, so Drive still shows everything.

## Where things go

| What you are saving | True copy | Work on it at | Gets back to the true copy by |
|---|---|---|---|
| Document, PDF, deck, spreadsheet for humans | Drive `00_Primary_Storage_Drive/`, filed by its `README.md` ladder | Drive desktop app, or `~/DEV/_DRIVE` | Drive sync (automatic) |
| Finished deliverable from a repo | Drive `00_Primary_Storage_Drive/03_REPORTS/`, named `YYYY-MM-DD_<Sport>_<Topic>_<Type>_<Audience>.<ext>` in full words (`2026-10-29_Football_GPS_WeeklyReport_Coaches.pdf`; rules: Drive `README.md` Naming) | made in `<repo>/outputs/` | `closeout` copies it (copy, keep the repo one) |
| Code, scripts, project docs, `STATUS.md` | GitHub `erash11/<repo>` | `~/DEV/<repo>` | `git commit` + `git push`, every session |
| Generated output (charts, exports, logs) | `<repo>/outputs/` | same | regenerate from code; gitignore it if large |
| Database (DuckDB, SQLite) | local disk, inside its repo or `~/DEV` | same | daily (daytime: hourly 12:00-17:00 via `scripts/daily-backup-login.sh`) `daily-backup.ps1` stages the live DBs (not dated `before`/`backup` copies) into `dev-databases.tgz`, uploaded via `gws` to Drive `_MACHINE/Backups/Machine` (since 2026-10-20; one copy, no history) |
| Secrets (`.env`, tokens, keys) | macOS Keychain or local `.env` | same | nowhere else — never in git, Drive, or chat |
| Claude/Codex config, skills, memory | GitHub `dotclaude`, `claude-skills`, `claude-global-memory` | `~/.claude` | `git push` (daily-backup also pushes) — the home of each agent file kind is in "Agent files" below |
| A loose file with no home yet | `~/DEV/_INBOX/` | same | `weekly-review` drains it within 7 days |
| Temporary agent work | the session scratchpad | same | thrown away |

Identifiable athlete health data (`DexaProject`, case reviews like `SpecialRequests/TOS_ES`) stays
where it is: local or its one Drive folder. Never push it to GitHub, never paste it into chat or an
external service. A folder with a `CLAUDE.md` saying "local only" is in this class.

## Agent files (decided 2026-10-24)

One home per kind. Every other copy is a symlink to it, a generated view, or gone.

- **Instructions, settings:** the `~/.claude` root, tracked by the dotclaude whitelist. The backup of a tracked config file is its git history: never leave a `.bak` copy beside it (dotclaude ignores `**/*.bak*`); commit before a risky edit. Untracked root files (`machine.md`, `~/.claude.json`) have no backup beyond the CRASHBOX SSD layer.
- **Hook scripts:** `~/.claude/hooks/`. `~/.codex/hooks` is a symlink to that whole folder (2026-10-24), so both harnesses run the same files; anything written into `~/.codex/hooks` lands in dotclaude. Never remove or reorder an entry in `~/.codex/hooks.json`: Codex keys its trusted hashes by entry position.
- **Installed tools:** `~/.claude/skill-router` is staged by `~/DEV/TypeSafe_Sandbox/skill_router/install.py`; edit the source and reinstall, never in place. `~/.claude/permission-gate` holds the shadow log written by `TypeSafe_Sandbox/permission_gate`.
- **Skills:** owned skills in `~/.claude/skills` (claude-skills). `~/.codex/skills` and the owned links in `~/.agents/skills` are generated by `~/.claude/skills/sync-to-codex.sh`. `~/.agents/skills` is the third-party pool: no bulk installs.
- **Plugins, caches, app state:** app-owned (`~/.claude/plugins`, `cache/`, `backups/`, `jobs/`, `context-mode/`, `~/.codex/packages`, `plugins`, `.tmp`, `~/Library/Application Support/Claude`). Tidy them only with the app's own commands (`claude plugin uninstall`, `ctx_purge`). Never move them by hand; never put your files inside.
- **Memory facts:** Tier B `~/.claude/global-memory/{USER,MEMORY}.md`; Tier A `~/.claude/projects/<slug>/memory/`, where the slug is the absolute cwd with every non-alphanumeric (`_` included) turned to `-`; repo facts in `<repo>/docs/`.
- **Handoffs:** `<repo>/docs/handoffs/`; workspace or system work with no single repo: `~/DEV/docs/handoffs/`. `~/.claude/global-memory/handoffs/` is read-only history.
- **Audits:** `~/.claude/audits/YYYY-MM-DD-<topic>.md` (the script-bound `KeystoneOS/docs/audits/` and the vault's `SecondBrain/audits/` excepted). Audit clock: `~/DEV/KeystoneOS/docs/rot.md`, the one copy.
- **Logs and alerts:** job logs in `~/.claude/scripts/logs/`; a tool's own log in its own folder, never at the `~/.claude` root. Clear `.errors.log` only by appending it to `transcripts/.errors-ledger.log`.
- **Search roots:** `~/DEV/KeystoneOS/data/memory-index-paths.json` lists every record home above. `harvest-dev-docs.sh` mirrors repo docs into it and skips the health and local-only class above. Never run `memsearch index` by hand.
- **Retired:** projects to `~/DEV/_ARCHIVE/`, drained copies to `~/_PARKED_COPIES/`, proven clutter to `~/.Trash/<name>-<date>`.

## Machine-written copies (backups)

Scripts write to Drive `_MACHINE/`. Humans browse `00_Primary_Storage_Drive/`. Nothing lives in both.

- `_MACHINE/Cloud_Copy/DEV` — one-way mirror of `~/DEV`, minus databases, secrets, and regenerable/catalog
  caches (`printing-press-library`, `graphify-out/cache`, `.build`, `node_modules`, `.venv`, `__pycache__`).
  Written by `~/.claude/scripts/cloud-push.py` (07:00 and 17:30).
- `_MACHINE/Backups/Machine` — daily (daytime: hourly 12:00-17:00 via `scripts/daily-backup-login.sh`) `.tgz` snapshots of `~/.claude/projects`, Codex, Gemini, and LaunchAgents
  uploaded directly by `gws` API (`daily-backup.ps1` `Snapshot-Gws`); `zotero.tgz` (`~/Zotero` database, PDFs,
  styles) at most weekly and only when Zotero changed (`Snapshot-Zotero`, since 2026-10-23); plus SSD captures of repo data git does not
  carry from `~/.claude/scripts/backup-manifest.json`.
- External SSD `CRASHBOX` — second daily copy when CRASHBOX is plugged in at midday.

Read a backup to restore. Edit only the true copy. To add a path to the backups, add it to
`backup-manifest.json`; a path missing from the manifest is not backed up.

## How agents reach Drive

- Read, list, move, and upload through the API: the `gws` CLI (`gws drive files …`), or the Drive MCP.
  Moves keep file IDs; use `gws drive files update` with `addParents`/`removeParents`.
- The mount (`~/Library/CloudStorage/GoogleDrive-…`) is for Eric and for `cloud-push.py`. Agent
  reads through it can hang, and its view can lag the server by days. Before trusting the mount,
  compare its folder list with `gws drive files list`.
- `gws --upload` only takes a path inside the current directory: `cd` to the file's folder first.

## Places that are never a destination

Baylor OneDrive, `~/Desktop`, `~/Downloads`, and the Drive root. If something lands in one of
these, file it by the table above in the same session.

## Before you finish a session

- Every repo you touched: committed and pushed.
- Every deliverable you made: copied to `03_REPORTS/`.
- Every new top-level folder in `~/DEV`: has a `portfolio.json` row (`new-project` does this).
